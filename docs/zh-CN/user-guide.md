# 使用指南

[English](../user-guide.md) · [README](../../README.zh-CN.md)

## 任务模型

每个活跃的 Paseo workspace 对应一个 Workboard 任务。导入时，没有受管理状态标签的 workspace 会进入**待归类**；导入本身不会补写标签。

草稿是尚未关联 workspace 的任务。只需标题即可记录，以后再继续。默认情况下，新建草稿和显式带有 `task:todo` 标签的 workspace 会进入**待开始**。草稿可以移到待归类而不绑定 workspace；移到其它工作分组时会要求创建或关联 workspace。

任务状态是业务决策。Agent 的运行、等待输入和报错等状态会单独显示。Agent 会话结束不会把任务标记为已完成。

## 使用任务

### 创建与开始

从看板创建草稿，或在待开始类型分组的快速创建控件中输入标题。草稿在选择**开始工作**前没有 workspace、会话或 Agent。

开始工作时可创建新 workspace 或关联已有 workspace。新建 workspace 会保留草稿标题和说明；关联已有 workspace 时保留原 workspace 名称，并将草稿标题和说明合并到备注，因此始终是一张任务卡。开始工作不会创建 Agent 或发送消息。默认进入第一个进行中类型分组；若不存在，请先配置分组。

### 改变状态

每个分组都有关联的受管理 workspace 标签。默认映射如下：

| 类型   | 默认标签           |
| ------ | ------------------ |
| 待归类 | `task:inbox`       |
| 待开始 | `task:todo`        |
| 进行中 | `task:in-progress` |
| 待验收 | `task:review`      |
| 已完成 | `task:done`        |
| 已废弃 | `task:canceled`    |

可通过状态菜单或拖动桌面卡片的把手改变状态。移动已绑定任务会更新其受管理标签；修改原生标签也会更新看板。普通标签会保留。若同时存在多个受管理状态标签，Workboard 会提示冲突，可选择一个状态修复。

桌面拖动超过 6px 后开始，显示卡片预览、突出目标列，并在靠近横向边缘时自动滚动。按 `Esc`、窗口失焦或在看板外松手都会取消。每个分组按最后活跃时间排序：已绑定任务取最后一次已验证对话，草稿取最后编辑时间，没有对话的 workspace 排在末尾。不支持在同一分组内手动排序。

## 使用看板

桌面与 Web 中，Workboard 跟随 Paseo 的语言设置。支持中文和英语，其它 Paseo 语言回退到英语；Paseo 跟随系统语言时，插件采用相同的语言选择规则。插件没有独立语言设置。默认分组名称与日期随界面切换，自定义分组名、任务标题和说明保持原文。

### 阅读卡片

卡片显示标题、项目、活动和最近对话日期。展开可查看标签、Agent 和完整 PR/MR 标题。Paseo 提供信息时，卡片还会用原生风格图标显示 PR/MR 状态、CI 结果和评审结论。Workboard 不会直接查询 forge。PR/MR 合并或关闭不会改变任务状态。

需关注包括等待、报错和未读活动；标签或同步冲突；需要核实的对话、归档、Git、terminal 或目录问题；以及开放或草稿 PR/MR 的 CI 失败或要求修改。已合并、已关闭和暂不可用的 PR/MR 不会沿用旧 CI 结果触发提醒。聚焦、悬停或点击说明图标可查看原因。

### 筛选与视图调整

可按项目、文本、需关注、Agent 活动和 PR/MR 条件筛选。筛选只保存在当前客户端和 Paseo host。筛选无结果时可以清除筛选或新建任务。

桌面可调整分组顺序、列宽、折叠状态、颜色和定位。列宽及折叠状态是当前客户端、当前 host 的本地偏好。折叠只影响显示；成功拖入折叠分组的卡片会使该列再次展开。

“定位分组”按钮会打开分组列表。选择桌面分组会展开并滚到该列；窄屏会切换到该分组。窄屏一次显示一个分组，方向键切换分组，`Home` 和 `End` 跳到首尾。

## 配置分组

分组包含名称、类型、受管理标签和显示颜色。颜色只影响显示，不会修改标签、任务规则、置顶或归档。列头、卡片细色条、状态选项、窄屏页签和分组设置会使用同一颜色。新分组优先推荐未使用的颜色，之后推荐使用次数最少的颜色。

至少保留一个待归类和一个待开始类型分组。待归类接收未管理状态的 workspace；待开始接收草稿，以及默认映射下显式 `task:todo` 的 workspace。删除分组前必须先移走任务。分组弹窗保存后立即生效；通用设置使用独立的保存操作。

调整分组顺序只改变显示位置，不会改变草稿默认去向，也不会改变开始工作时选择哪个进行中分组。

## 归档 workspace

自动归档默认关闭。启用后，Workboard 只考虑位于已完成或已废弃分组、且最后一条已验证用户或助手对话超过 30 天的任务。它不会把改标签时间、编辑任务时间、工具调用或导入时间视为对话活动。

归档前，如果无法验证对话历史，或 workspace 有运行/等待的 Agent、terminal、运行脚本，或 Git 状态不安全/无法核实，Workboard 会延期。它不会自动 stash、commit、push 或删除文件。

自动归档调用 Paseo 原生 workspace 归档。这可能停止 Agent 与 terminal，并可能移除托管 worktree。成功需要原生响应 `error=null` 且存在 `archivedAt`，随后刷新确认 workspace 已从原生活跃列表消失；不确定结果会保留供人工处理，不会盲目重试。

未绑定且位于已废弃分组的草稿可以从看板手动归档。它没有原生 workspace，不需要等待 30 天，也无法恢复 worktree。

Paseo 原生的 **Archive merged PR workspaces** 设置是独立功能。它按自己的合并观察和安全检查工作，不等待 30 天，也不会把 Workboard 任务改为已完成。

## 置顶进行中 workspace

侧边栏置顶默认开启，按分组的**进行中**类型判断，而不按 Agent 是否运行。任务进入进行中分组时 Workboard 会添加侧边栏置顶；离开时只会取消它能识别为自己创建的置顶。

手动置顶会保留。如果在任务仍处于进行中时手动取消自动置顶，Workboard 在这次停留期间不会强行恢复；离开再进入后可以重新置顶。关闭开关会移除 Workboard 创建的置顶，保留手动置顶。

原生置顶 API 不提供 owner 或比较并交换能力。崩溃或并发原生变化导致结果不确定时，Workboard 会保留置顶，避免误删手动置顶。

## 限制与支持边界

- Workboard 精确面向 Paseo 0.9.1；升级后的内部标签桥接可能需要调整。
- 本地筛选、列宽和折叠列按客户端与 host 保存，不是共享任务数据。
- workspace 标签以及原生归档/置顶可以在 Workboard 外变化。插件会尽可能重读状态，但原生 API 不提供所有原子操作。
- Paseo 0.9.1 中已归档 workspace 的历史可能不完整。Workboard 会保守处理不完整的对话证据，并延期自动归档。
